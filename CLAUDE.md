# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
cargo build                   # build
cargo run -- server --allow <client-id> -t '*'                             # run as server, open TCP proxy (socks5/http/tunnel to anything)
cargo run -- server --allow <client-id> -t localhost:22 -f -r -v media:/media  # run as server: tunnel to one target, file send + rsync into a volume
cargo run -- client socks5 --listen 127.0.0.1:1080 -n <node-id>            # run as SOCKS5 proxy client
cargo run -- client http --listen 127.0.0.1:8080 -n <node-id>              # run as HTTP proxy client
cargo run -- client tunnel --listen 127.0.0.1:9000 --remote-host remote_host --remote-port 3000 -n <node-id>  # run as tunnel (ssh -L style) client
cargo run -- client file <path> -n <node-id> -t media/subdir               # send a file to a server volume
cargo run -- client volumes -n <node-id>                                   # list the server's exposed volumes
cargo run -- client whoami                                                 # print this client's node id (for the server's --allow)
rsync -av -e "'target/debug/proxy-rs' client sync-rsh -n <node-id>" ./dir/ "x:media/subdir/"  # rsync push over iroh
cargo clippy                  # lint
cargo test                    # run unit tests (-t pattern matcher in src/protocols/proxy/target_policy.rs, authorized-clients parsing in src/authorized_clients.rs, message framing in src/protocols/codec.rs)
cargo test -- --ignored       # run the e2e smoke test (see below)
just                          # list the justfile recipes (build/check/e2e/server/socks5/http/tunnel/send/sync/docker/armv7 wrappers)
```

The binary is `proxy-rs`.

### End-to-end test (`tests/e2e/`)

`tests/e2e.rs` has one `#[ignore]`d test, `socks5_proxy_smoke_test`, wrapping [tests/e2e/socks5_proxy.sh](tests/e2e/socks5_proxy.sh). It's `#[ignore]`d (not run by plain `cargo test`) because it needs `ncat` installed and real processes/ports: it starts an `ncat` HTTP listener on `127.0.0.1:4001` that replies `hello`, gets the client's node id via `client whoami`, starts a `proxy-rs` server (with `-t localhost:4001` and `--allow <that id>` only) and a SOCKS5 `proxy-rs` client (both built by `cargo test` via `CARGO_BIN_EXE_proxy-rs`, run against a temp working directory with `HOME` also pointed at it, so `~/.proxy-rs/server-key` and `~/.proxy-rs/known-servers` don't touch the real dev files), waits for the server to print its NodeId and the client's SOCKS5 listener to come up, then curls `http://localhost:4001/` through the proxy with `--socks5-hostname` (the `-t` allowlist matches hostnames, so curl must not resolve locally) and asserts on the response body, then curls `localhost:4002` and asserts it's refused with SOCKS5 reply `0x02` (curl exit 97). Then it starts a second client with its own `--config-dir` (so a different key) and asserts it fails with "not in its allowlist". Finally it stops the server with SIGINT and asserts the SOCKS5 client (no `--retry`) exits non-zero with `Disconnected from`. Run it with `cargo test -- --ignored`.

## Architecture

This is a P2P proxy built on [iroh](https://github.com/n0-computer/iroh). The server exposes itself as an iroh node; clients connect by node ID rather than IP address. All traffic is multiplexed over iroh's QUIC-based transport using ALPN protocol negotiation.

### Mode selection (main.rs)

The single binary takes a `server` or `client` subcommand (`clap::Subcommand`, each with its own `#[derive(Args)]` struct). `client` itself carries a second, nested subcommand (`ClientMode`) selecting exactly one of its seven modes — no `ArgGroup` needed, the subcommand enum is the mutual-exclusion mechanism:
- `server` → exposes only the features enabled by flags (see "Server feature gating" below); `-v`/`--volume` declares directories for `-f`/`-r` to write into
- `client socks5` / `client http` → TCP proxy client, `-l`/`--listen <addr>` is purely a local bind address now (previously a `protocol://host:port` URL whose scheme selected the mode — replaced by these being separate subcommands)
- `client tunnel` → ssh `-L`-style forwarding; `-l`/`--listen <addr>` (local bind) plus `--remote-host`/`--remote-port` (fixed remote target)
- `client file <path>` → file sender client (positional path), writing into a server volume (`-t`/`--target` selects which)
- `client volumes` → prints the server's exposed volumes as `name:path`, one per line
- `client whoami` → prints this client's node id (from `client-key`) and nothing else on stdout: the `proxy-rs vX.Y.Z client whoami` banner and logs go to stderr, like `sync-rsh`, so `$(proxy-rs client whoami)` works; no network
- `client sync-rsh` → rsync transport over iroh (`proxy-rs/rsync/2`), not run directly but passed to rsync's `-e` in place of `ssh`: `rsync -av -e "'<proxy-rs>' client sync-rsh -n <node-id>" ./dir/ "x:<volume>/<dir>/"`. The host before `:` is a placeholder; the path must start with a server volume name. Push only; requires `-n`/`--name` (stdin is rsync's pipe, so no interactive menu), and `rsync` installed on both ends

`-n`/`--node-id` and `--name` are global on `client` (valid before or after the mode subcommand), since every mode needs to resolve a server node id. `--config-dir`/`-d` is global on the whole binary (valid before or after `server`/`client` and, for `client`, before or after the mode too) and overrides the persistent state directory (see below); if omitted, it defaults to `~/.proxy-rs`.

Every other flag can also be set via an env var, prefixed with its subcommand: `PROXY_RS_CONFIG_DIR` (global, so no subcommand); on the client `PROXY_RS_CLIENT_NODE_ID`, `PROXY_RS_CLIENT_NAME`, `PROXY_RS_CLIENT_LISTEN`, `PROXY_RS_CLIENT_REMOTE_HOST`, `PROXY_RS_CLIENT_REMOTE_PORT`, `PROXY_RS_CLIENT_FILE`, `PROXY_RS_CLIENT_OVERWRITE`, `PROXY_RS_CLIENT_TARGET`, `PROXY_RS_CLIENT_RETRY`; on the server `PROXY_RS_SERVER_TARGET`, `PROXY_RS_SERVER_ALLOW` (both comma-separated), `PROXY_RS_SERVER_FILE`, `PROXY_RS_SERVER_RSYNC`. An explicit CLI flag takes precedence. The `SERVER_`/`CLIENT_` prefix keeps same-named flags apart (e.g. server `-t` vs client `file -t`), so a shell that exports a client var can't silently open a server's proxy. `PROXY_RS_CLIENT_LISTEN` is shared by `socks5`/`http`/`tunnel`'s separate `--listen` fields — safe to reuse, since only one mode is ever active per invocation. `-v`/`--volume` (server) has no env var, since it's repeatable.

### Server feature gating (`src/server.rs`, `src/protocols/proxy/target_policy.rs`)

`run_server` only registers the ALPNs for enabled features on the iroh `Router`; unregistered ALPNs fail the QUIC handshake. Ping is always on. `-t/--target <pattern>` (repeatable; `--tunnel` is a hidden alias, its old name) enables TCP proxying via `TargetPolicy`, `-f/--file` enables file send, `-r/--rsync` enables rsync push, and list-volumes is on if `-f` or `-r` is. Startup fails if nothing is enabled, if `-v` is given without `-f`/`-r`, or `-f`/`-r` without `-v`. `-t '*'` prints a WARNING (open proxy); `-r` without `rsync` on `PATH` prints a WARNING.

**Client allowlist** (`src/authorized_clients.rs`): enforced by `ClientGate`, an iroh `EndpointHooks` impl installed on the server endpoint (`.hooks(...)`), whose `after_handshake` sees every incoming connection (remote id + ALPN) before the `Router` hands it to a protocol handler, so protocol handlers know nothing about it. Allowed = `--allow` ids (parsed at startup) ∪ ids in `<config-dir>/authorized-clients` (one per line, `#` comments; text after the id is an optional label), and the file is **re-read on every connection** (`ClientAllowlist::check`) so edits add/revoke/relabel without a restart; a read/parse error logs and fails closed to `--allow` only. Refused connections are closed with reason `not allowed` (same as iroh's `AccessLimit`); the client's `ping_server` checks `conn.close_reason()` for that and reports its own node id with a hint. For accepted connections on the ping ALPN only (every client holds its ping connection open as a session for as long as it runs; other ALPNs, e.g. one connection per proxied socket, would be too noisy) the gate prints `Client connected: <label> [<short id>]` (or just the short id if unlabeled), and spawns a task on `conn.weak_handle().closed()` (a weak handle, never a `Connection` clone: iroh's hook docs warn that a strong handle kept from a hook keeps the connection alive) that prints `Client disconnected: ...` with a ` (reason)` suffix unless the close was deliberate (`stream_helpers::close_reason_suffix`). The connected line ends with ` (relay)`/` (direct)` (the connection's selected iroh path, `stream_helpers::PathKindWatch::suffix`, or `path_kind_suffix(&conn)` for a one-off; omitted if none is selected yet), and that same task prints `Client <client> now direct` (or `now relay`) whenever the selected path switches kind (`PathKindWatch::run`, driven by iroh's `Connection::path_events()` `Selected` events; it subscribes before reading the initial kind so no switch is missed, and re-reads on `Lagged`) — connections usually start on the relay and get upgraded once holepunching succeeds. Likewise `ProxyServerProtocol` prints one line per proxied TCP connection: `tcp [<short id>] -> host:port` (the target exactly as the client sent it, no DNS lookup shown), or `... refused: not allowed by -t` / `... failed: <error>`. If both sources are empty (checked per connection, so it tracks file edits), the gate admits everyone; startup prints `Allowed clients: any` and a WARNING. A file read/parse error still fails closed, even with no `--allow`.

There's deliberately one TCP ALPN for SOCKS5/HTTP/tunnel, not one per mode: they're identical on the server (dial `host:port`), so per-mode gating couldn't separate anything; a client could just use whichever ALPN is enabled. The real distinction is which targets are reachable, hence the allowlist.

`-t` patterns: `host:port` or bare `*` (= `*:*`). Host is exact, `*`, `*.domain` (one or more labels in front, not the bare domain), or bracketed IPv6 `[::1]`. Port is exact, `*`, or inclusive `lo-hi`. `*.*` and unbracketed IPv6 are rejected at parse time. Hosts are compared lowercased with a trailing `.` stripped, against the **hostname string the client sends, before DNS**, so `localhost` ≠ `127.0.0.1`.

### Protocol layer (`src/protocols/`)

Each protocol is a self-contained directory with four files: `alpn.rs` (constant string), `*_header.rs` (message struct), `*_protocol_handler.rs` (server-side `iroh::protocol::ProtocolHandler` impl), and `mod.rs`.

**Wire format** (`src/protocols/codec.rs`) — every protocol message is a plain `#[derive(Serialize, Deserialize)]` struct, sent as a frame: `u32` big-endian length, then that many bytes of [postcard](https://docs.rs/postcard). The blanket `StreamCodec` impl gives every such type `msg.encode(&mut send)` / `T::decode(&mut recv)`. Frames over `MAX_FRAME_LEN` (64 KiB) are refused on encode (nothing written) and on decode (before allocating), so no length is ever silently truncated, and a reader always consumes exactly one whole message.

**Versioning is by ALPN only** — messages carry no version field. Postcard isn't self-describing (no field tags, no skipping unknown fields), so *any* change to a message struct (including `Ack`) is a breaking change: bump the trailing number of that protocol's ALPN in its `alpn.rs` (constants are unversioned, e.g. `TCP_PROXY_ALPN`; the version lives only in the string). A mismatched peer then fails the QUIC handshake (TLS alert 120, "no application protocol") instead of mis-decoding bytes; the client's `connect` helper in `client.rs` turns that into `server does not accept protocol <alpn>: ...`, a version mismatch for ping (always enabled) or "feature not enabled, or incompatible version" for the others.

The main protocols and their ALPN strings (also `proxy-rs/list-volumes/2` and `proxy-rs/rsync/2`):
| Protocol | ALPN | Purpose |
|---|---|---|
| Ping | `proxy-rs/ping/2` | Pre-flight health check before every client operation |
| TCP Proxy | `proxy-rs/tcp/3` | Sends `ProxyHeader { host, port }`, receives `Ack` (0 connected, 1 not allowed by `-t`, 2 connect failed), then raw bidirectional TCP |
| File Send | `proxy-rs/file/2` | Sends `FileSendHeader`, receives `Ack`, streams bytes, receives final `Ack` |

### Client flow (`src/client/`)

Every mode starts with a one-line summary: `BANNER` (`proxy-rs vX.Y.Z`, in `main.rs`) plus mode and settings, e.g. `proxy-rs v0.1.2 server tcp=*:* file rsync clients=any` (volumes follow as `  volume <name> -> <path>` lines) or `proxy-rs v0.1.2 client tunnel 127.0.0.1:9000 -> host:22`; each `run_*` prints its own, except whoami/sync-rsh, whose banner `main.rs` prints to stderr. Every banner ends with ` config=<dir>` (`config_dir::banner_suffix`, absolute path, shown whether default or set by `--config-dir`/`PROXY_RS_CONFIG_DIR`); `main.rs` applies the override before anything prints. Node ids on the console are shortened with `identity::short_id` (`3f1eb...58d`: first 5 and last 3 chars) everywhere except the two places they must be copied: the server's last startup line (the bare id) and `client whoami`. `client.rs` always pings the server first, then opens the appropriate ALPN connection. `ping_server` returns the ping connection, which callers keep open (`_session`) for their whole run; a `NotAllowed` error type marks an allowlist refusal. Clients behave like ncat/telnet by default: no server, or losing it, means exit with an error (non-zero). Every networked mode shows `Connecting to <server>` right after resolving the server, before the endpoint comes up (getting online is part of the wait), as a `client::spinner::Spinner`: an indicatif spinner (each new spinner takes the next frame set from `FRAME_SETS` in turn, and with `--retry` `maintain_session` calls `Spinner::next_frames()` after each failed attempt, so every retry is visible; message and elapsed time carry on) with elapsed time on stdout when it's a terminal, else one plain `Connecting to <server>...` line; it's cleared on `finish()` or drop (so an error starts on a clean line) and replaced by `Connected to ...`. sync-rsh only logs it, since its stdout is rsync's pipe. Long-running modes (socks5/http/tunnel) run `maintain_session` alongside their listener; it prints `Connected to <server> (relay|direct)` / `Connection to <server> now direct|relay` (on a path switch, like the server's gate). Without `--retry` (the default) `run_tcp_client` pings *before* binding the listener (so an offline server exits before anything listens) and hands that connection to `maintain_session`, which returns `Err(Disconnected from <server>[ (reason)])` when it closes, ending the client. With `--retry` (only on socks5/http/tunnel, env `PROXY_RS_CLIENT_RETRY`; the banner gets a ` retry` suffix) the listener binds immediately (the spinner keeps going: `maintain_session` takes it and finishes it on connect) and `maintain_session` prints `Disconnected from ...` then starts a `Reconnecting to <server>` spinner instead, prints `Waiting for <server>: <err>` above the spinner (which keeps its `Connecting to`/`Reconnecting to` text) on the first failed attempt (at startup, and after each loss) only, retries 2s after each attempt ends, and only returns on `NotAllowed`. One-shot modes (file/volumes/sync-rsh) never retry. How long one attempt takes is up to iroh: a node id with no published address fails in ~3-5s (the client's `connect` helper reports it as `server [...] is not online (no address found for its node id)`), while a server killed without a clean close (its DNS record outlives it) times out after QUIC's idle timeout (~30s), which is also when a connected client notices such a server is gone. A server stopped with a signal closes cleanly and is noticed at once. For TCP proxy mode it runs a `TcpListener` and spawns a task per connection; each task does a SOCKS5 or HTTP handshake locally before opening the iroh stream. The local success reply (SOCKS5 `REP 0x00`, HTTP `200 Connection Established`) is **not** sent by `socks5::handshake`/`http::handshake`; the handlers send it only after `open_proxy_stream` gets the server's `Ack`, and map refusals to SOCKS5 `0x02`/`0x05`/`0x01` or HTTP `403`/`502`. Tunnel mode has no local protocol, so a refusal just closes the local socket and logs an error. `client tunnel --listen <local> --remote-host <host> --remote-port <port>` skips the local handshake entirely (ssh `-L`-style): the listener binds `<local>` and every accepted connection is proxied straight to the fixed `<host>:<port>` via `TCP_PROXY_ALPN`. The server side needs no changes for this — `ProxyHeader { host, port }` is an opaque target the server checks against its `-t` policy and dials, so SOCKS5/HTTP/tunnel differ only in how the client-local `(host, port)` is obtained; `main.rs` picks which via the `ClientMode` subcommand and passes a typed `ProxyType` + bind address + optional `(remote_host, remote_port)` into the single shared `run_tcp_client`, rather than parsing a `protocol://` URL scheme at runtime.

Byte-shuffling (iroh bi-stream ↔ local read/write) lives in `stream_helpers.rs`: TCP uses `proxy_streams` (`tokio::io::copy_bidirectional`, so half-close propagates and it waits for both directions); rsync uses `proxy_process_streams` (`select!`, ssh-style: done when either side ends, since rsync only closes our stdin after we exit). Both finish the send stream and await `stopped()` before returning, because the caller then drops the `Connection`, which would otherwise discard in-flight data.

`client_helpers.rs` manages saved server node IDs in `~/.proxy-rs/known-servers`, same format as `authorized-clients` (`<node-id> [name]` per line, name optional, `#` comments; both are parsed by `src/id_file.rs`). Each node id has at most one entry (one name per id): saving an id that's already present renames its line in place (and drops any duplicate lines for it) via `save`/`rewrite`, otherwise the entry is appended (the file is created with a comment header); every other line is kept, so hand edits and comments survive. Names are case-sensitive. Unnamed servers are shown as just `[3f1eb...58d]` (`server_label`). Names are auto-generated as `Adjective Animal` using built-in word lists (no extra deps). Passing `--node-id` always skips the menu below and uses that ID directly (saving it under an auto-generated name if not already known). Otherwise (including when only one, or zero, IDs are saved) `dialoguer::Select` always prompts the user with every saved entry as `Name [3f1eb...58d]`, plus a trailing `<new>` entry; picking `<new>` prompts with `dialoguer::Input` for a node ID, validated as a parseable `EndpointId`, then prompts for a name (defaulting to an auto-generated `Adjective Animal`, shown in `[brackets]` and used as-is on empty Enter), then saves both (`add_new_server`). If the id is already saved, the name prompt defaults to its current name. If a *different* saved server already has the entered name, a `dialoguer::Confirm` (`[y/N]`, default no) asks whether to replace it: yes removes that server's entry, no re-prompts for the name. (With both `-n` and `--name` on the command line, the same clash is an error instead, since there's no one to ask.)

### Signals (`src/signals.rs`)

Ctrl-C (SIGINT), SIGTERM and SIGHUP are caught and reported as `Received <signal>, shutting down` (`signals::announce`; on a terminal it first clears the line holding the echoed `^C`). SIGKILL can't be caught, so it can't be reported. The server awaits `shutdown_signal()`, announces, then `router.shutdown()` closes every client connection cleanly (clients notice at once) and exits 0. Client modes socks5/http/tunnel/file/volumes wrap their work, including `endpoint.online()`, in `until_signal(...)`: on a signal it drops the work (clearing any spinner), announces, and returns `signals::Interrupted`, after which the existing `endpoint.close()` still runs (so the server logs `Client disconnected` at once, not after the idle timeout); `main.rs`'s `failed()` turns `Interrupted` into a quiet exit with `128 + signo` (130 Ctrl-C, 143 SIGTERM, 129 SIGHUP) instead of an `Error:` line. sync-rsh and whoami keep the default signal behavior (sync-rsh's stdout is rsync's pipe, and rsync reports interruptions itself).

### Persistent state (`~/.proxy-rs/`)

These files live in `~/.proxy-rs` by default, resolved by `config_dir()` in `src/config_dir.rs`, created on first run:
- `server-key` — hex-encoded `iroh::SecretKey`; determines the server's stable node ID.
- `client-key` / `client-key.pub` — same pair, for the client; every client endpoint uses it so the server's allowlist can recognize it. Both keys are loaded by `identity::load_or_create_secret_key`, which also refreshes the `.pub` file, and are created with mode 0600, race-safely (write temp file, `hard_link` into place, which fails if another process won; everyone then reads the winner's key).
- `authorized-clients` — server-side client allowlist (see "Server feature gating"); if missing, the server creates it at startup (`create_new`, never overwrites) with a comments-only template (no ids, so on its own the server stays open).
- `server-key.pub` — the server's node ID (public key), written/refreshed alongside `server-key` on every server start, so it's readable without parsing the secret key.
- `known-servers` — client-side list of known server node IDs, `<node-id> [name]` per line (written by the client, editable by hand).

`main.rs` calls `config_dir::set_config_dir_override()` before dispatching to a mode when `--config-dir`/`-d` is passed, pointing `config_dir()` at that directory instead (used as-is, not joined with `.proxy-rs`).

### HTTP proxy handling (`src/http.rs`)

`http::handshake()` returns a `ProxyRequest { host, port, is_connect, preamble }` and writes nothing back. CONNECT tunnels (`is_connect`, empty preamble) get `http::respond_connected()` from the caller once the server has acked; plain HTTP requests carry the original request bytes as preamble so the server forwards them to the upstream. Refusals go out via `http::respond_error()`.
